# AETHER 商业化封版优化执行方案

目标：先把工程质量和核心编辑语义稳定住，再做体验统一和商业化交付能力。本文只列可执行、可验证、可回归的任务；不把“继续加组件”作为当前主线。

## 0. 总结判断

当前软件的问题不是功能少，而是编辑器、预览和导出之间的渲染语义还没有完全统一。最容易反复出现的老问题，基本都来自“同一个元素在不同运行路径里有不同判断”。

必须优先处理三件事：

1. 时间线是唯一真相：元素只在 `[startTime, startTime + duration)` 内参与画面合成，结束点不显示。
2. 编辑器、预览、导出共用同一套可见性和样式描述，避免各自复制判断。
3. 类型检查、乱码、异常文案和导出授权链路必须归零，否则不能进入商业发布。

验收：

- `npm run test` 通过。
- `npm run build` 通过。

### 1.2 乱码和异常文案清理

## 2. P0 统一编辑器、预览、导出渲染层

### 2.1 时间线可见性统一

执行点：

- 新建纯函数模块：`src/core/render/timeline.ts`。
- 统一时间窗语义：`currentTime >= startTime && currentTime < startTime + duration`。
- `duration <= 0` 的元素不显示。
- `duration === Infinity` 的元素从开始时间后常显。
- Canvas 渲染、子图层渲染、导出运行时代码全部使用同一语义。

验收：

- 指针在素材开始前：不显示。
- 指针等于素材开始点：显示。
- 指针在素材中间：显示。
- 指针等于素材结束点：不显示。
- 指针在素材结束后：不显示。
- 相关单元测试覆盖以上边界。

### 2.2 渲染描述层逐步抽离

目标模块：

- `src/core/render/elementDescriptor.ts`
- `src/core/render/timeline.ts`
- `src/core/render/style.ts`

统一输出：

- 元素是否参与当前时间点合成。
- 元素基础位置、尺寸、旋转、透明度。
- 文本样式、字体、描边、阴影、发光。
- 图片、视频、UI 组件、自定义代码组件、图表、3D/VFX 的渲染参数。

约束：

- 编辑态只能额外显示选框、控制点、辅助线，不能改变最终画面合成结果。
- 预览和导出必须优先复用同一套描述，而不是各写一套判断。
- 拆分必须分批进行，每批都保持用户可见行为不变。

## 3. P1 文字系统统一

执行点：

- 修复系统字体读取后字体下拉无法展开的问题。
- 所有文字相关入口共用同一个字体选择控件和字体列表状态。
- 图片、文字、UI 组件、自定义代码组件统一 8 控制点缩放逻辑。
- 文字样式统一进入一个模型：字号、行高、字距、描边、阴影、发光、预设样式。

验收：

- 所有文字图层都能展开字体下拉并完成选择。
- 所有文字图层都能通过 8 控制点调整尺寸。
- 编辑器、预览、导出中文字外观一致。

## 4. P1 组件库体验一致

执行点：

- 内置组件、自定义组件、仪表盘组件统一卡片、右侧预览、插入按钮、空状态、错误状态。
- 任意组件点击后先进入右侧预览，点击“插入当前组件”后才写入场景。
- 缩略图和大预览使用同一预览容器规范。
- 增加最近使用、收藏、搜索、分类过滤。

验收：

- 新增 UI 组件和历史内置组件交互一致。
- 无预览、加载失败、代码报错都有明确提示。
- 预览画面居中展示完整组件，不裁切关键内容。

## 5. P1 核心文件拆分

拆分顺序：

1. `CanvasViewport.tsx`：拆出时间线可见性、元素容器、控制点、文本编辑、弹窗交互、视频同步。
2. `InspectorPanel.tsx`：拆成 Text/Image/Shape/UI/Interaction/Timeline/Advanced inspector。
3. `utils/export.ts`：拆成 HTML 模板、元素序列化、运行时脚本、资源打包、HUD。
4. `GalaxyComponents.tsx`：拆成按钮、图表、仪表盘、交互控件。

验收：

- 每次拆分后 `npm run lint`、`npm run test`、`npm run build` 全绿。
- 不改变现有用户可见行为。
- 新增逻辑优先进入 `core/*` 或 `utils/*` 纯函数，组件只负责渲染和交互。

## 6. P2 商业化交付能力

执行点：

- 移除用户路径中的 `window.alert`，统一 Toast/Dialog/ErrorBoundary。
- 建立统一 logger 和可导出的诊断包。
- 导出失败报告包含工程版本、浏览器、素材缺失、授权状态、错误栈摘要。
- 自定义代码组件、导出 HTML、iframe、innerHTML 建立统一安全策略。
- 增加版本号、工程格式迁移、崩溃恢复、离线授权策略和旧工程回归集。

验收：

- 用户遇到错误时能知道原因、下一步和可复制诊断信息。
- 商业授权、导出、工程导入导出形成闭环。
- 自定义代码组件错误不会拖垮整个编辑器。
