# 设备实时监控大屏扩展开发文档

> 版本：v0.1
> 日期：2026-09-10
> 适用范围：鲸动交互平台现有 React/Vite 编辑器、HTML 导出运行时与 Node/Express 服务。

## 1. 目标与边界

本方案将现有“交互媒体编辑器”扩展为可编辑、可发布、可实时监控设备状态的运营大屏平台。参考原型为“充电桩数据可视化”：全国地图为主视图，左右两侧展示 KPI、趋势、告警、站点和设备明细，并支持区域筛选与钻取。

编辑器负责模板编排、可视化绑定和发布；设备接入、时序存储、告警计算及权限审计必须由服务端承担。禁止浏览器直接连接 PLC、充电桩、局域网 Modbus 或厂商设备接口。

## 2. 原型功能映射

| 原型区域 | 业务能力 | 当前基础 | 本次扩展 |
|---|---|---|---|
| 顶部标题、日期、全局时间 | 项目标题、环境、实时钟 | 文本/场景已有 | `实时钟` 与全局筛选器组件 |
| 左侧 KPI 卡 | 设备总数、在线率、充电量、故障数 | 文本、形状、图表已有 | 指标卡组件与实时数据绑定 |
| 左下趋势图 | 负荷、订单、能耗等时间序列 | 图表元素已有 | 折线/面积/柱状图时序绑定 |
| 中央中国地图、站点标签 | 地域分布、站点状态、区域钻取 | 2D/3D、热点已有 | GeoMap、聚合点、地图交互事件 |
| 右侧地图与告警摘要 | 站点定位、活跃告警、处置状态 | 普通图层已有 | 告警列表、地图缩略组件 |
| 右侧明细和排行 | Top N、设备运行状态、利用率 | 图表元素已有 | 表格、排行、状态灯与分页 |
| 时间筛选、区域筛选、标签点击 | 联动、钻取、返回全局 | 场景跳转/热点已有 | 变量上下文、筛选器、事件总线 |

## 3. 需具备的系统能力

### 3.1 设备侧与接入侧

1. 设备唯一标识：`tenantId + siteId + deviceId`，不可仅使用展示名称。
2. 设备协议适配：充电桩优先 OCPP 1.6J/2.0.1；工业设备按 MQTT、OPC UA、Modbus TCP 或厂商 HTTP API 适配。
3. 边缘网关：部署在设备网络内，负责协议转换、断网缓存、证书与上行重试；不能开放设备端口到公网。
4. 统一上报格式：网关将厂商报文归一化后上送消息总线。
5. 时钟要求：网关和服务端必须 NTP 校时；每条数据携带设备时间、网关接收时间与服务端入库时间。

### 3.2 平台侧

1. 设备注册与资产台账：租户、区域、站点、设备、型号、坐标、额定参数。
2. 实时状态服务：计算在线、离线、故障、运行、空闲、维护等当前状态。
3. 时序数据服务：保存功率、电量、电压、电流、温度、SOC、会话等历史指标。
4. 规则与告警服务：阈值、持续时长、恢复条件、去重、升级、确认、关闭。
5. 查询 API 与实时网关：HTTP 获取初始快照；WebSocket/SSE 推送增量；订阅必须受租户、角色和范围约束。
6. 认证与审计：OIDC/JWT、RBAC、访问范围、告警操作与配置变更审计。

## 4. 推荐架构

```text
设备 / 充电桩 / PLC / 厂商云
        |
协议适配与边缘网关（OCPP / MQTT / OPC UA / Modbus）
        |
消息总线（MQTT Broker 或 Kafka / NATS）
        |
设备接入服务 --> 状态计算服务 --> Redis 当前状态缓存
        |                   |                 |
        |                   +--> 告警规则服务  +--> WebSocket 网关
        v
时序数据库（TimescaleDB / InfluxDB） + PostgreSQL 资产与权限库
        |
查询/BFF API（HTTPS，JWT，租户隔离）
        |
鲸动编辑器 / 已发布 HTML 大屏
```

### 技术选择

| 层 | 最小可行选型 | 生产建议 |
|---|---|---|
| 消息接入 | EMQX/Mosquitto + MQTT | EMQX 集群或 Kafka/NATS，按吞吐量选择 |
| 业务 API | 在 `server/` 新增受认证的 BFF | 独立 `monitoring-api` 服务，避免与 AI 3D 代理共进程 |
| 当前状态 | 内存缓存 | Redis Cluster，设置 TTL 和设备心跳判定 |
| 元数据/权限 | SQLite | PostgreSQL |
| 时序数据 | PostgreSQL 表分区 | TimescaleDB 或 InfluxDB，按保留策略降采样 |
| 推送 | WebSocket | WebSocket 网关 + Redis Pub/Sub/Kafka Consumer |
| 地图 | GeoJSON + Canvas/WebGL | MapLibre GL JS，离线瓦片或合规地图服务 |

## 5. 数据契约

### 5.1 资产与最新状态

```ts
type DeviceStatus = 'online' | 'offline' | 'idle' | 'running' | 'fault' | 'maintenance';

interface DeviceAsset {
  tenantId: string;
  siteId: string;
  deviceId: string;
  name: string;
  type: 'charger' | 'meter' | 'sensor' | 'gateway' | 'custom';
  regionCode: string;
  location: { lng: number; lat: number };
  ratedPowerKw?: number;
  tags?: string[];
}

interface DeviceSnapshot {
  deviceId: string;
  status: DeviceStatus;
  updatedAt: string;
  metrics: Record<string, number | string | boolean | null>;
  version: number;
}
```

### 5.2 设备遥测归一化事件

```json
{
  "eventId": "01J...",
  "tenantId": "tenant_demo",
  "siteId": "site_bj_001",
  "deviceId": "charger_001",
  "eventTime": "2026-09-10T14:20:00.000Z",
  "receivedAt": "2026-09-10T14:20:01.125Z",
  "metrics": {
    "powerKw": 42.6,
    "energyKwh": 18234.8,
    "voltageV": 380.2,
    "currentA": 64.1,
    "connectorStatus": "charging"
  },
  "quality": "good"
}
```

约束：事件按 `eventId` 幂等；允许乱序写入；`eventTime` 不可用时采用 `receivedAt` 并标记 `quality=estimated`。数据质量异常不能覆盖较新的设备快照。

### 5.3 前端实时推送

连接：`wss://api.example.com/v1/realtime?projectId=...`。认证通过 `Sec-WebSocket-Protocol` 或短期访问令牌，禁止把长期密钥放在 URL、项目文件或导出包中。

```json
{
  "type": "snapshot.patch",
  "sequence": 12045,
  "scope": { "tenantId": "tenant_demo", "regionCode": "110000" },
  "data": {
    "deviceId": "charger_001",
    "status": "running",
    "updatedAt": "2026-09-10T14:20:00.000Z",
    "metrics": { "powerKw": 42.6 }
  }
}
```

客户端必须：按 `sequence` 去重；检测缺号后调用快照 API 补偿；指数退避重连；页面不可见时降频；显示“数据延迟/连接中断”而非伪造实时状态。

## 6. API 设计

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/v1/dashboard/snapshot` | 首屏 KPI、地图点位、告警和图表快照 |
| `GET` | `/v1/metrics/series` | 指标时间序列，参数含 `metric/from/to/interval/groupBy` |
| `GET` | `/v1/devices` | 设备筛选、分页、排序与状态查询 |
| `GET` | `/v1/devices/:deviceId` | 设备详情、最近遥测、关联告警 |
| `GET` | `/v1/alerts` | 告警列表和统计 |
| `POST` | `/v1/alerts/:alertId/ack` | 确认告警，要求操作权限和审计记录 |
| `GET` | `/v1/geo/sites` | 站点和聚合点 GeoJSON |
| `GET` | `/v1/realtime-token` | 为已发布大屏签发 5 分钟订阅令牌 |

所有接口强制 `tenantId` 从 JWT 声明解析，不信任前端传入的租户字段。查询响应包含 `generatedAt`、`dataLatencyMs`、`source`，便于大屏暴露数据新鲜度。

## 7. 当前程序的扩展设计

### 7.1 新增前端模块

```text
src/
  monitoring/
    client.ts            # HTTP API、令牌刷新
    realtime.ts          # WebSocket 生命周期、顺序与重连
    store.ts              # 外部数据快照和订阅状态
    selectors.ts          # KPI、TopN、地图点、趋势数据派生
    types.ts              # 资产、遥测、告警、查询契约
    mock.ts               # 编辑器演示数据，不可用于发布环境
  components/monitoring/
    MetricCard.tsx
    GeoMap.tsx
    AlarmList.tsx
    DeviceTable.tsx
    TimeRangeFilter.tsx
    DataFreshnessBadge.tsx
```

### 7.2 扩展现有类型与元素

在 `src/types/index.ts` 中增加以下元素类型：`metric-card`、`geo-map`、`data-table`、`alarm-list`、`filter-control`。每个数据型元素需配置：

```ts
interface DataBindingConfig {
  sourceId: string;             // 数据源定义 ID，不含秘密
  query: string;                // 受限的查询标识，不允许执行任意脚本
  refresh: 'realtime' | '10s' | '30s' | 'manual';
  mapping: Record<string, string>;
  emptyState?: 'placeholder' | 'hidden' | 'error';
}
```

复用 `src/utils/bindings.ts` 的变量绑定语义，但数据刷新应由 `monitoring/store.ts` 统一驱动，不能在每个元素内独立创建 WebSocket。

### 7.3 编辑器、预览、导出差异

| 场景 | 数据来源 | 要求 |
|---|---|---|
| 编辑器设计态 | `monitoring/mock.ts` 或录制快照 | 不连接生产设备，不写入实时系统 |
| 编辑器预览态 | 经授权的只读测试数据源 | 显示数据源、延迟、连接状态 |
| 发布大屏 | 环境变量指定的 BFF API | 通过短期 token 订阅，权限范围固定 |
| 静态离线导出 | 最后成功快照 | 明确显示“离线快照时间”，不标示实时 |

当前 `src/utils/export.ts` 与 `src/core/export/runtime3d.js` 的导出上下文需要新增 `runtime-monitoring.js`。导出包只保存 `sourceId`、查询和样式配置，不保存 MQTT 密钥、数据库密码、厂商 Token 或内部地址。

## 8. 模板与交互规范

1. 新建“设备监控大屏”模板：默认 3840×1080 超宽画布，也提供 1920×1080 版。
2. 地图点位颜色不应是唯一状态表达：增加图标、标签或形状区分在线/故障/离线。
3. 地图点击写入全局变量 `filters.regionCode` 或 `filters.siteId`；KPI、表格、告警和趋势图共同响应。
4. 设备行/告警行点击可打开详情抽屉或跳转详情场景；操作必须保留返回路径。
5. 指标卡显示统计口径和数据更新时间；无数据、延迟、权限不足、连接断开要有独立状态。
6. 高刷数据只更新数值与状态标记，地图和大图表采用 250-1000ms 批处理，避免逐条遥测触发 React 全树重渲染。

## 9. 告警、可用性与安全

### 告警状态机

`pending -> active -> acknowledged -> resolved -> closed`。告警规则必须支持持续时长、恢复阈值、去重键、抑制窗口和升级策略。大屏只显示读模型，不直接在前端判定生产告警。

### 可用性目标

| 指标 | 首期目标 |
|---|---|
| 状态端到端延迟 | P95 小于 5 秒 |
| 大屏首屏加载 | P75 小于 3 秒（同城网络、已有缓存） |
| 推送重连恢复 | 小于 30 秒，自动快照补偿 |
| 单屏数据更新 | 250ms 合并一次，避免抖动 |
| 设备离线判定 | 可按设备类型配置，默认心跳超时 180 秒 |

### 安全基线

1. 网关到云端使用 mTLS 或设备证书；禁止共享 MQTT 用户名密码。
2. 前端仅访问 BFF，不直连 Broker、时序库或设备网络。
3. JWT 中携带租户、角色和可访问区域；服务端每次查询二次校验。
4. 数据源配置采用服务端密钥引用 `secretRef`，项目 JSON 和浏览器存储不保存明文密钥。
5. 所有告警确认、模板发布、数据源修改记录操作者、时间、前后值与请求追踪 ID。
6. 对 WebSocket、筛选 API 和地图聚合 API 实行租户级限流、最大订阅数与最大返回点数。

## 10. 分阶段交付

### P1：可演示监控模板

新增监控模板、指标卡、地图点、趋势图、告警列表、全局筛选变量和录制数据回放。仅使用 mock/JSON 数据，验证编辑体验和导出 UI。

### P2：只读实时看板

建设资产表、快照 API、WebSocket 推送、Redis 当前状态、数据源面板与发布 token。先接入一个协议和一个租户；告警仅展示外部系统结果。

### P3：生产运营

接入 OCPP/MQTT 网关、时序库、规则引擎、告警确认、RBAC、审计、监控告警和容灾。完成压力测试、数据保留策略、脱敏与发布审批。

## 11. 验收清单

- 同一筛选条件下，地图、KPI、趋势、表格和告警结果一致。
- 断网、令牌过期、无权限、数据延迟、空数据均可识别且不误导为实时。
- 连续 1,000 条状态更新不会导致编辑器或已发布大屏明显掉帧。
- 重连后通过快照补偿，状态不会永久停留在旧值。
- 租户 A 无法通过 REST、WebSocket、导出包或修改请求读取租户 B 数据。
- 生产导出包和项目文件不含设备地址、秘密、数据库连接或长期 Token。
- 告警确认、关闭、配置变更均能追溯审计记录。

## 12. 启动决策

在编码 P2 前，业务方需要确认：首批设备类别与协议、预计设备数/每秒上报量、地域坐标来源、在线与告警口径、历史数据保存周期、部署网络边界，以及是否需要多租户和角色权限。未明确这些输入时，应只实施 P1 的录制数据模板，不应直接承诺“实时监控”。
