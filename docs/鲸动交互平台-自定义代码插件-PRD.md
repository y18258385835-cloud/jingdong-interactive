# 鲸动交互平台「自定义代码插件」PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品 | 鲸动交互平台 |
| 功能 | 自定义代码插件 |
| 文档版本 | V1.0 |
| 产品状态 | 需求设计 |
| 入口位置 | 顶部工具栏「AI交互」菜单下，位于「AI交互」下方 |
| 目标用户 | 设计师、前端开发者、数字展陈实施人员、交互方案制作人员 |

## 2. 功能概述

用户可以将 AI 生成或自行编写的前端代码粘贴到平台，在受控沙箱中即时预览 UI 组件和交互动效，并将验证通过的组件作为一个可编辑图层插入当前画布。

首期支持：

- HTML：组件结构与语义内容。
- CSS：布局、颜色、渐变、滤镜、关键帧动画和响应式样式。
- 原生 JavaScript：组件内部交互、状态切换、计时器和事件监听。
- 画布组件参数：位置、尺寸、旋转、层级、可见性和锁定状态。
- 组件编辑：重新打开代码插件，修改代码后更新已插入的画布图层。

首期不承诺直接运行任意 React、Vue、Svelte、Node.js 或需要 npm 安装的工程代码。此类代码应先转换为浏览器可直接运行的 HTML/CSS/原生 JS，或在后续版本增加编译型插件运行时。

## 3. 产品目标与边界

### 3.1 目标

1. 降低 AI 生成 UI 动效进入鲸动画布的门槛。
2. 让用户在插入画布前看到真实运行效果，避免把报错代码带入工程。
3. 保持代码插件与普通画布图层一致的定位、缩放、层级和导出管理能力。
4. 将代码运行限制在独立沙箱内，避免插件代码影响平台编辑器和用户本地环境。

### 3.2 首期不做

- 不执行 Node.js、Shell、Python 或其他服务端代码。
- 不允许插件直接访问平台 React 状态、工程数据、文件系统或浏览器 Cookie。
- 不提供任意外部 npm 包的在线安装与执行。
- 不把插件代码默认为平台级公共插件；首期仅保存到当前工程或用户本地插件库。
- 不自动将代码发布到公网或上传到第三方服务。

## 4. 入口与信息架构

### 4.1 菜单位置

顶部工具栏：

```text
AI交互 ▾
├── AI交互        [AI]
└── 自定义代码插件 [插件]
```

菜单项使用代码括号或终端类图标，颜色沿用 AI 交互分类的紫色体系。点击后打开「自定义代码插件」工作区，不直接把代码写入当前画布。

### 4.2 进入条件

- 无当前工程时：允许打开并预览，但“插入画布”置灰，并提示先创建或打开工程。
- 有工程但无活动场景时：允许预览；插入时提示选择或创建活动场景。
- 有活动场景时：可完成预览、校验、插入和更新。

## 5. 功能描述

### 5.1 代码输入

用户可通过以下方式提供代码：

- 直接粘贴完整 HTML 文档。
- 分栏粘贴 HTML、CSS、JavaScript。
- 粘贴 Markdown 代码块，系统自动识别 `html`、`css`、`javascript`/`js` 标记。
- 点击“清空”恢复空白模板。
- 从当前插件草稿或最近一次代码恢复。

系统应显示代码语言识别结果、字符数、估算资源体积和校验状态。

### 5.2 沙箱预览

点击“运行预览”后，平台将代码组装到独立 iframe 沙箱中：

- 预览区默认显示组件实际视觉效果，不添加平台说明文字覆盖层。
- 支持鼠标、触摸、键盘焦点、点击、悬停和拖动等组件内部交互。
- 支持刷新预览、暂停动画、打开控制台错误面板和查看运行耗时。
- 预览容器提供背景色、透明背景、视口宽度和高度设置。
- 预览内容超出边界时只在预览区内滚动或裁切，不推动平台页面布局。

### 5.3 加入画布

预览通过基础校验后，用户点击“加入画布”：

- 将沙箱中的代码封装为一个 `custom-code` 类型画布图层。
- 以当前画布中心为默认位置，按预览尺寸换算为画布百分比宽高。
- 组件作为一个整体移动、缩放、旋转、复制、隐藏、删除和调整层级。
- 默认锁定宽高比；用户可在 Inspector 中解除锁定。
- 插入后保留代码、预览配置、插件名称和版本信息。
- 画布编辑器中不执行插件内部 DOM 编辑；需要改代码时重新打开插件编辑器。

### 5.4 编辑与更新

选中已插入的 `custom-code` 图层后，Inspector 提供“编辑代码插件”入口：

- 打开该图层绑定的代码和预览配置。
- 运行新代码并通过校验后，提供“更新当前图层”与“另存为新图层”。
- 更新失败时保留当前画布图层和上一份可运行代码。
- 更新成功后保留画布位置、尺寸、旋转和层级，除非用户明确选择重置几何属性。

## 6. 用户操作流程

### 6.1 新建并插入组件

1. 用户点击顶部「AI交互」。
2. 点击「自定义代码插件」。
3. 输入插件名称，可选填写描述和作者。
4. 粘贴 AI 生成的 HTML/CSS/JS 代码，或使用分栏模板。
5. 点击“运行预览”。
6. 系统进行语法检查、安全检查和运行检查。
7. 预览区加载组件；若有问题，在错误面板展示文件、行号、错误类型和修复建议。
8. 用户在预览区验证按钮、动效和响应式表现。
9. 点击“加入画布”。
10. 系统关闭或保留插件工作区，按用户选择将组件插入当前活动场景。
11. 用户在画布中调整位置、尺寸、旋转和层级。

### 6.2 修改已插入组件

1. 用户选中画布中的自定义代码图层。
2. 在 Inspector 点击“编辑代码插件”。
3. 修改代码并运行预览。
4. 通过校验后点击“更新当前图层”。
5. 系统只替换代码内容，保留图层几何属性。
6. 用户可撤销更新或另存为新图层。

### 6.3 失败恢复

1. 代码运行报错时，预览区显示上一次成功版本或空状态。
2. 用户查看错误位置和错误信息。
3. 点击“恢复上次可运行版本”或修复后再次运行。
4. 未通过安全检查时，禁止加入画布，但允许用户导出错误报告或继续编辑。

## 7. 页面原型说明

### 7.1 工作区结构

```text
┌────────────────────────────────────────────────────────────────────┐
│ 自定义代码插件                         [保存草稿] [运行预览] [关闭] │
├──────────────────┬──────────────────────────────────┬──────────────┤
│ 插件信息         │ 预览区                           │ 运行检查     │
│                  │                                  │              │
│ 名称             │ 组件实时渲染                     │ 状态：通过   │
│ 描述             │                                  │ 代码体积     │
│                  │ [刷新] [暂停] [透明背景]          │ 错误/警告     │
├──────────────────┤                                  │              │
│ 代码编辑器       │                                  │              │
│ [HTML][CSS][JS]  │                                  │              │
│                  │                                  │              │
│ 粘贴/编辑代码    │                                  │              │
│                  │                                  │              │
│ [格式化] [清空]  │                                  │              │
├──────────────────┴──────────────────────────────────┴──────────────┤
│ [导入示例] [恢复版本] [下载代码]       [加入画布]                  │
└────────────────────────────────────────────────────────────────────┘
```

### 7.2 左侧代码区

- 顶部为 HTML、CSS、JS 三个标签页。
- 编辑器需支持等宽字体、行号、语法高亮、错误行标记和搜索。
- 粘贴完整 HTML 时，系统可自动拆分 `<style>` 与 `<script>` 到对应标签。
- 编辑器底部显示字符数、行数和当前语言。
- 粘贴超出限制时立即提示，不截断后静默执行。

### 7.3 中部预览区

- 使用固定比例预览框，默认 `16:9`，可切换自适应、桌面、移动和大屏尺寸。
- 预览区边缘显示轻量边界，不添加会遮挡组件的说明文字。
- 组件内部滚动只影响 iframe 内容。
- 提供“重新加载”“暂停动画”“打开控制台”三个图标按钮，并提供悬停提示。

### 7.4 右侧检查区

检查区分为三类状态：

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| 未运行 | 代码尚未执行 | 运行预览 |
| 检查中 | 正在解析、加载和执行 | 取消运行 |
| 可插入 | 运行成功且无阻断问题 | 加入画布 |
| 有警告 | 可以运行，但存在性能或兼容性风险 | 查看警告、仍可插入 |
| 有错误 | 无法稳定运行或违反安全限制 | 查看错误，禁止插入 |

### 7.5 插入确认

点击“加入画布”后显示轻量确认区：

- 插入到：当前场景 / 选择场景。
- 初始位置：画布中心 / 当前视口中心。
- 初始尺寸：按预览比例 / 自定义宽度。
- 是否锁定宽高比：默认开启。
- 操作按钮：取消、加入画布。

## 8. 安全限制

### 8.1 执行隔离

- 代码只能在 `iframe sandbox="allow-scripts"` 内运行，不授予 `allow-same-origin`、表单提交、弹出窗口、下载或顶层导航权限。
- iframe 使用独立文档，不共享平台 DOM、React 状态、LocalStorage、IndexedDB、Cookie 和工程数据。
- 插件代码不能通过选择器访问平台外层节点。
- 组件插入画布后仍以隔离运行时渲染，不将用户代码拼接进平台主文档。

### 8.2 网络与资源

- 默认禁止外部网络请求；`fetch`、XHR、WebSocket、EventSource 和动态脚本加载需被拦截。
- 首期允许内联 CSS、内联 JS、数据 URI 和平台已授权的资源引用。
- 外部图片、字体、视频和脚本默认阻止；如未来开放白名单，需按域名、协议和资源类型审批。
- 不允许 `javascript:`、`data:text/html` 导航和动态创建顶层窗口。

### 8.3 代码与能力限制

- 禁止或拦截 `eval`、`Function`、动态 `import()`、Web Worker、Shared Worker、Service Worker、WebRTC、MIDI、地理位置、剪贴板写入和设备传感器访问。
- 禁止访问文件系统、系统命令、进程、环境变量和平台密钥。
- 限制 iframe 最大 DOM 节点数量、脚本执行时间、定时器数量和内存使用；达到阈值时停止预览。
- 限制 `canvas` 尺寸和动画帧开销，避免展厅大屏上出现无限重绘。
- 插件不能修改父页面标题、URL、快捷键和平台全局样式。

### 8.4 内容与合规

- 平台不保证 AI 生成代码的版权、许可证和内容合规性。
- 用户在插入前应确认代码来源、第三方资源授权和展示内容合法性。
- 保存工程时记录插件来源为“用户粘贴代码”，便于后续审计和问题定位。

## 9. 输入规则

### 9.1 基础字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `name` | 是 | 1-40 个字符，不得为空白 |
| `description` | 否 | 最多 200 个字符 |
| `html` | 否 | 与 CSS 或 JS 至少一项非空；最大 100 KB |
| `css` | 否 | 最大 100 KB |
| `js` | 否 | 最大 100 KB |
| `viewport` | 否 | `responsive`、`desktop`、`mobile`、`custom` |
| `width`/`height` | 否 | 自定义视口时为 160-3840 px、90-2160 px |
| `background` | 否 | `scene`、`transparent`、合法颜色值 |

### 9.2 代码规范

- 推荐使用相对单位、CSS 变量和组件根节点选择器。
- 不依赖平台外层选择器、全局 ID 或固定窗口尺寸。
- 动画应优先使用 `transform` 和 `opacity`，避免持续改变 `width`、`height`、`top`、`left`。
- 组件根节点建议使用唯一类名，避免内部样式冲突。
- JS 应在 DOM 加载后初始化，并在卸载时清理定时器和事件监听。

### 9.3 粘贴识别

系统按以下顺序处理粘贴内容：

1. 识别 Markdown fenced code block。
2. 识别完整 HTML 文档并提取 `body`、`style`、`script`。
3. 识别包含 CSS 选择器和 JS 语句的混合片段，提示用户确认拆分结果。
4. 无法识别时原样放入当前编辑器，不自动执行。

## 10. 输出规则

### 10.1 插件对象

```ts
type CustomCodePlugin = {
  id: string;
  version: number;
  name: string;
  description?: string;
  source: {
    html: string;
    css: string;
    js: string;
  };
  preview: {
    mode: 'responsive' | 'desktop' | 'mobile' | 'custom';
    width?: number;
    height?: number;
    background: 'scene' | 'transparent' | string;
  };
  diagnostics: {
    status: 'idle' | 'passed' | 'warning' | 'error';
    errors: Diagnostic[];
    warnings: Diagnostic[];
    checkedAt: string;
  };
  createdAt: string;
  updatedAt: string;
};
```

### 10.2 画布图层

插入画布后生成：

```ts
type CustomCodeElement = SceneElement & {
  type: 'custom-code';
  customCodePluginId: string;
  customCodeVersion: number;
  customCode: CustomCodePlugin;
};
```

画布图层必须继续遵守现有 `x`、`y`、`w`、`h`、`rot`、`zIndex`、`visible`、`locked` 和场景归属规则。导出时保留代码插件的隔离运行边界，不把代码提升到宿主页面执行。

## 11. 异常处理与代码报错提示

### 11.1 错误分类

| 类型 | 示例 | UI 反馈 | 是否允许插入 |
| --- | --- | --- | --- |
| 语法错误 | JS 缺少括号、CSS 解析失败 | 标出文件、行号、列号和错误信息 | 否 |
| 运行时错误 | `undefined is not a function` | 控制台面板显示堆栈，预览标记失败 | 否 |
| 超时 | 初始化超过 2 秒或脚本持续阻塞 | “组件运行超时，已停止沙箱” | 否 |
| 安全阻断 | 使用 `fetch`、`eval`、动态脚本 | 标出被阻断 API 和替代建议 | 否 |
| 资源错误 | 图片或字体加载失败 | 显示资源地址和失败原因 | 有警告时可插入 |
| 性能警告 | 长时间高频重绘、DOM 过多 | 显示指标和优化建议 | 是，需用户确认 |
| 插入失败 | 当前场景不存在或工程写入失败 | 保留代码草稿，提示重试 | 否 |

### 11.2 报错信息格式

```text
运行错误
JS · 第 18 行，第 9 列
TypeError: Cannot read properties of undefined

建议：确认 querySelector 返回值存在后再绑定事件。
[定位代码] [复制错误] [恢复上次版本]
```

要求：

- 用户可点击错误定位到对应编辑器行。
- 错误信息不得只显示“运行失败”，必须包含错误类型和可操作建议。
- 不向用户暴露平台内部路径、密钥、完整宿主堆栈或沙箱实现细节。
- 预览崩溃时自动终止 iframe，并提供“一键重新加载”。

## 12. 用例

### 用例 1：AI 生成数据指标卡

**角色**：前端设计师  
**前置条件**：已打开 1920×1080 工程并进入活动场景。  
**操作**：粘贴 HTML/CSS/JS 指标卡，运行预览，点击卡片切换数值状态，加入画布。  
**结果**：指标卡作为一个 `custom-code` 图层插入画布，保持内部动效和外部图层编辑能力。

### 用例 2：AI 生成展厅按钮扫光

**角色**：数字展陈实施人员  
**操作**：粘贴包含 hover 扫光和点击反馈的按钮代码，使用透明背景预览，确认移入和移出状态后插入画布。  
**结果**：按钮直接作为画布组件存在，不新增平台文字或说明浮层；用户可调整按钮位置与尺寸。

### 用例 3：代码存在网络请求

**角色**：交互设计师  
**操作**：粘贴包含 `fetch('/api/data')` 的代码并运行。  
**结果**：检查区提示网络请求被沙箱策略阻断，给出“改用静态 JSON 或平台数据绑定”的建议，禁止插入未验证版本。

### 用例 4：修改已插入组件

**角色**：前端开发者  
**操作**：选中画布中的组件，将 CSS 的主色和动画时长改为新值，运行后更新当前图层。  
**结果**：代码版本递增，画布位置、尺寸、旋转和层级保留，更新可撤销。

### 用例 5：AI 输出 React 代码

**角色**：不熟悉前端构建的用户  
**操作**：直接粘贴带 `import React`、JSX 和 npm 包依赖的代码。  
**结果**：系统识别为非首期支持格式，提示“请转换为 HTML/CSS/原生 JS，或等待编译型插件支持”，不执行、不插入。

### 用例 6：脚本死循环

**角色**：任何用户  
**操作**：粘贴持续阻塞主线程的脚本并运行。  
**结果**：沙箱达到执行时间阈值后被终止，显示超时错误，平台编辑器保持可用，用户可以修改代码后重试。

## 13. 验收标准

1. 用户能从「AI交互 > 自定义代码插件」进入独立工作区。
2. HTML/CSS/原生 JS 代码可在沙箱中渲染，并支持组件内部交互。
3. 代码错误能显示文件、行号、错误类型和可执行建议。
4. 通过检查的组件能插入当前画布，并成为可移动、缩放、旋转、排序的单一图层。
5. 插件代码无法访问平台 DOM、工程状态、Cookie、文件系统或默认网络。
6. 插入后的组件可以重新打开、修改、验证和更新，更新失败不破坏旧版本。
7. 网格、吸附、选择框和现有画布编辑能力不因插件图层失效。
8. 预览区和平台主界面在代码报错、超时、资源失败时均不崩溃。
9. 工程保存、导入和导出能够保留插件代码、版本和预览配置。
