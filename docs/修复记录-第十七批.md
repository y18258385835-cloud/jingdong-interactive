# 修复记录 · 第十七批（安装包实机验证 + 服务端打包）

## 1. 发现并修复：安装版服务端缺依赖（P0）

按 `installer.iss` 安装到干净目录后，启动器拉起 `runtime\node.exe server\index.js` 直接报错：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'express' imported from ...\server\index.js
```

原因：安装包只复制了 `server\*`，没有 `node_modules`，桌面端的 AI / 授权 / 控制桥 / 通知接口在用户机器上全部不可用。

### 修复方式

- 新增 `tools/bundle-server.mjs`：用 esbuild 把 `server/index.js` 及其依赖打包成单文件 `server/bundle.mjs`（2.52 MB）
- 打包产物与 `license-admin.html` 同目录，`import.meta.url` 相对路径保持不变
- `app_launcher.cs`：优先运行 `server\bundle.mjs`，不存在时回退 `server\index.js`
- `npm run build` 末尾自动执行 `node tools/bundle-server.mjs`
- `.gitignore` 忽略 `server/bundle.mjs`（构建产物）

## 2. 修复：`runtime/node.exe` 导致 Vite dev 崩溃

`npm run dev` 会监听整个仓库；`runtime/node.exe`（80 MB）被杀毒/系统锁定时触发：

```
Error: EBUSY: resource busy or locked, watch '...\runtime\node.exe'
```

修复：`vite.config.ts` 的 `server.watch.ignored` 忽略 `runtime/`、`release/`、`data/`、`promo/out/`。

## 3. 安装包实机验证（Windows）

```bash
npm run build        # 前端 + 播放器 + 服务端单文件
npm run build:exe    # 启动器
iscc installer.iss   # 安装包（23.3 MB）
```

静默安装到临时目录后检查：

| 检查 | 结果 |
|---|---|
| 安装目录结构 | `dist/`、`server/`、`public/`、`runtime/node.exe`、启动器 exe 全部存在 |
| `server/bundle.mjs` | 存在 |
| 用内置 node 启动服务端 | `GET /api/health` → **200** |
| 授权后台（桌面端应关闭） | `GET /admin/licenses` → **404** ✅ |
| 控制桥 | `GET /api/control/handshake` → **200** ✅ |
| 播放器运行时 | `dist/export-player/index.html` 存在（由启动器静态服务） |

> `/export-player/index.html` 在 node 端口上返回 404 是预期行为：静态资源由启动器的 3388 端口提供，node 只负责 API。
