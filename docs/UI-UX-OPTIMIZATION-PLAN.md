# 鲸动交互平台 UI 与体验优化方案

## 产品目标

把当前功能丰富的沉浸式交互编辑器，逐步优化为“第一次使用也能完成作品、熟练用户能快速编辑、复杂工程状态可信”的桌面创作工具。保留现有 React、Three.js、工程数据协议、编辑器能力和暗色工业视觉，不以大规模重写作为优化目标。

## 用户与主要任务

- 新用户：理解软件能做什么，从空白或模板开始，完成第一个可预览、可保存的作品。
- 日常创作者：组织场景与图层，在画布上编辑内容，调整动画时间，预览并导出。
- 展示部署者：检查素材完整性、发布工程，在目标屏幕上稳定展示。

## 设计原则

1. 画布是工作台的视觉中心，工具和属性围绕当前任务组织。
2. 高频操作直接可见，低频和高级功能按需展开。
3. 空状态、处理中、成功和失败都给出清楚的下一步。
4. 关键文字易读，状态不只依赖颜色表达。
5. 以桌面编辑为主；窗口不足以容纳完整工作台时，明确降级或提示，不让关键操作静默裁切。
6. 继续使用现有工程协议和组件，改变小步、可验证、可回退。

## 优化阶段与验收

### 阶段 1：首次创作与基础可读性（核心项完成）

- [x] 空白场景提供添加文字、导入图片、添加图形的直接操作。
- [x] 空白提示说明属性面板、时间轴和拖入素材的下一步。
- [x] 时间轴关键标注从 9–10px 提升到至少 11px。
- [x] 新建空白工程后，在 1280×720 实测空状态和引导按钮；添加文字后提示消失、图层出现在时间轴、属性面板显示文字设置。
- [x] 用键盘验证画布空状态添加文字入口；自动化回归验证 Enter 添加及刷新后的保存恢复。

### 阶段 2：工作区层级与窗口适配（布局优化已完成，状态记忆仍待核验）

- [x] 窄窗口展开面板时显示提示，并提供“折叠侧栏”快捷操作；横向滚动区域显示滚动条提示。
- [x] 1280×720 展开工作区实测工具栏、左右面板、时间轴及空状态入口可见。
- [x] 900×700 实测窄屏提示出现，点击后可折叠侧栏；390×844 实测顶部保存、预览、导出与全屏入口仍可发现，面板默认折叠时保留画布区域。
- [x] 将全屏演示按钮在小屏改为仅显示图标，避免 sm 断点以下直接隐藏全屏入口。
- [x] 在 1440×900、1920×1080 验证展开工作台无页面级横向溢出；键盘验证弹窗焦点顺序和面板展开入口。
- [ ] 单独验证时间轴横向滚动区域的键盘滚动，以及重载后面板状态记忆。
- 注：390px 下该产品仍是桌面优先编辑器，不视为移动端完整支持；复杂编辑建议使用更宽窗口。

### 阶段 3：信息架构与任务流（本轮完成新建入口文案切片）

- [x] 梳理新工程入口：明确新建从空白画布开始、导入/列表用于已有工程、模板从工作台预设库加载；实测空工程入口可继续进入画布比例选择且可取消返回。
- 对高复杂功能采用渐进披露：先提供常用参数，高级参数放入可展开分组。
- [x] 统一“新建空白工程”在工程管理、文件菜单和快捷键一览中的名称；快捷键说明补充将进入画布比例选择。
- [ ] 继续检查其他常用操作在菜单、工具栏和空状态中的术语与完成反馈。
- [x] 检查不可逆工程删除及覆盖入口：删除确认明确说明“删除后无法恢复”，新建/加载官方示例前会提示未导出修改将被替换。
- [ ] 对素材删除、全局清空与替换素材分别核验影响范围和恢复方式。
- [x] 验收核心首次路径：无需离开画布入口即可创建空白工程、键盘添加文字、保存并刷新恢复；全产品所有常用功能的“两层入口”仍未穷举。

### 阶段 4：保存、素材与导出可信度

- [x] 显示未保存、保存中、已保存和保存失败状态；手动保存失败时有重试入口，并避免旧工程异步保存结果覆盖当前状态/恢复备份。
- [x] 批量素材导入显示当前文件、文件序号进度、可停止后续导入入口和失败文件名；已说明停止在当前文件完成后生效。
- [x] 导出已有格式/授权校验、阶段进度、视频中止、错误提示与再次导出入口（复核 AdvancedExportModal 现有实现）。
- [ ] 模拟 IndexedDB 写失败、离线、不支持文件、丢失素材与导出中断的完整恢复路径；本轮没有注入存储故障或执行完整编码导出。

### 阶段 5：可访问性与一致性

- [x] 画布设置和工程管理弹窗具备初始焦点、Tab 循环、Esc 关闭与焦点恢复；加入 Playwright 键盘回归。已检查核心高频图标操作具有可访问名称。
- [x] 已有深色主题基础焦点态、语义保存状态和 prefers-reduced-motion 规则；本轮增加焦点环 CSS token。
- [ ] 检查剩余全部弹窗、快捷键冲突、拖拽替代、全组件颜色对比和错误/禁用状态的非颜色表达；axe 本轮扫描工程管理与画布设置弹窗严重/危急问题。
- [ ] 将更多散落的间距、字号、边框与状态色迁移到 token（需按组件渐进执行，避免全局视觉回归）。

### 阶段 6：体验回归与性能

- [x] 新增 Playwright E2E：空白工程创建、键盘加文字、保存刷新恢复、弹窗键盘管理、1440/1920 无页面横向溢出；执行 5 条真实浏览器测试。
- [x] 新增 axe-core 工程管理与画布设置弹窗扫描并通过严重/危急问题门槛。
- [ ] 覆盖撤销/重做、项目导入/导出、错误恢复和演示大屏浏览器路径。
- [ ] 使用代表性大工程检查长时间轴、媒体加载、面板滚动和缩放性能，并建立可比较基线。
- [ ] 将 axe 扫描扩展至创作工作台、导出弹窗及其他核心页面；本轮不据单一弹窗扫描宣称全站无障碍完成。

## 优先级

1. P0：保存状态、工程恢复、素材与导出失败反馈；任何可能造成数据丢失的路径。
2. P1：首次创作流程、主工作区层级、窄窗口可操作性和时间轴可读性。
3. P2：键盘/无障碍、视觉 token、一致性和细节动效。
4. P3：引入新架构或替换依赖。只有现有实现无法满足已验证需求时才评估。

## 给 AI 编码助手的执行指令

```text
你正在改进“鲸动交互平台”现有代码库。目标是提高桌面创作编辑器的可发现性、可读性、可靠性和任务完成效率，不是重写产品。

执行规则：
1. 先阅读根目录和目标目录中的 AGENTS.md、相关组件、样式、类型和测试；确认工作区已有改动，禁止覆盖或回滚未要求处理的内容。
2. 每次只做一个可验证的小阶段。先描述本阶段目标、涉及文件、风险和验收方式，再实现；无需等待确认即可在用户已授权范围内继续。
3. 保留 React/Three.js 架构、现有工程 schema、保存兼容性、快捷键和导出协议。任何 schema 或数据迁移必须有兼容方案和回归测试。
4. UI 文案使用简洁中文，按钮动词明确；继续沿用现有深色工业工作台风格。不要为了装饰添加无意义渐变、发光、卡片或动画。
5. 桌面优先但必须实测不同窗口尺寸。窄窗口不能静默裁掉保存、预览、导出等关键动作；无法完整编辑时提供明确的折叠/精简模式或尺寸提示。
6. 空状态应提供可执行动作；加载、保存、导入和导出都要有进行中、成功、失败及恢复反馈。危险操作需可理解且能撤销或确认。
7. 交互控件要有键盘焦点、可访问名称和合理触控尺寸。颜色不能是表达状态的唯一方式，并尊重 prefers-reduced-motion。
8. 修改前后用浏览器走真实流程并截图；运行 npm run lint、相关测试，涉及广泛逻辑时运行 npm test。报告未能验证的路径。
9. 不以增加依赖或大规模重构代替问题解决。新依赖必须说明现有实现为什么不足、包体/迁移/维护成本和收益。
10. 每阶段完成后总结：用户可见变化、改动文件、验证结果、遗留问题和下一阶段建议。不要顺手修改无关功能。

按 docs/UI-UX-OPTIMIZATION-PLAN.md 的阶段和优先级执行。当前继续完成阶段 3 中信息架构与任务流的可验证小切片，并保留阶段 1、2 的未完成验收项。
```
