# 修复记录 · 第八批（英文界面可用性 + 全流程巡检）

## 1. 英文界面补齐高频残留

英文模式此前只有顶部菜单和侧栏是英文，右侧属性面板、时间轴、场景类型全部是中文。本轮扩充了 `interfaceTranslations`（404 → 450 条）：

- 属性面板：场景设置 / 基础 / 外观 / 动效 / 交互 / 数据 / 场景名称 / 单场景停留时长 / 全局轮播间隔 / 场景呈现类型 / 画布比例 …
- 场景与图层：场景序列与路径 / 设为起始 / 添加场景 / 删除场景 / 复制场景 / 图层顺序 / 编组 …
- 时间轴与工具栏：时间轴 / 折叠面板 / 搜索轨道 / 对齐 / 分布 / 锁定 / 隐藏 / 显示 …
- 场景类型与转场：弹窗场景 / 淡出 / 推入 / 擦除
- 通用动作：上传 / 拖拽 / 已复制 / 加粗 / 倾斜 / 下划线

另外新增一条正则规则：`总时长（秒）` → `Total Duration (s)`，覆盖所有「…（秒）」后缀的标签。

同时把「外观 / 交互」在英文下改为更短的 `Style / Actions`，避免 5 列属性页签被截断成 `App… / Inter…`。

## 2. 全流程巡检脚本

新增 `promo/usability-sweep.mjs`，用 Playwright 依次执行：

语言切换 → 工程管理 → 新建空白工程 → 添加文字图层 → 撤销/重做 → UI 组件库（懒加载看板） → 官方组件 → 导出面板 → 激活弹窗 → 刷新后工程恢复

结论：

- 所有入口均能正常打开/关闭，没有崩溃或白屏
- 懒加载的看板组件在打开组件库后正常出现
- 刷新后工程能恢复
- 未发现新的运行时错误

## 3. 英文模式的已知限制

DOM 翻译器是「整段文本精确匹配」的，因此：

- 组合文本不会被翻译，例如 `🎬 画布场景`（emoji + 文本同一节点）
- 用户自己写的工程名、图层名、场景名保持原样（这是期望行为）

要彻底解决，需要把界面文案改成资源文件（`t('key')`）而不是 DOM 事后替换，属于独立工程。
