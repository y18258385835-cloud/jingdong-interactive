# 自定义代码「蓝色选框不贴合」修复记录

> 现象：自定义代码组件（如图表/统计卡片）选中后，蓝色选框明显比组件本身宽，右侧和底部留出大片空白，拖动手柄也不跟内容对齐。

## 根因

不是选框绘制错了，而是**量错了对象**：

1. **量的是 iframe 视口，不是组件内容**
   `scaleToViewport()` 为了导出/预览一致，把 `#aether-custom-code-root` 强制成 `width:100%; height:100%`。
   旧的 `measureVisibleBounds()` 只测量这个 root，所以永远得到整个 iframe 矩形。内容比 iframe 窄时，选框就比内容大一圈。

2. **初次挂载的 1×1 测量被当成最终尺寸**
   画布 iframe 在布局完成前可能先以 `1×1` 挂载，并发出一次 bounds。旧逻辑会把这次测量当成“已贴合”，标记 `customCodeAutoFitted=true`。随后真正的 `362×224` 测量到达时被忽略。

3. **老工程已经标记过 fitted，永远不会重算**
   `customCodeAutoFitted` 是一次性标记。之前按 iframe 视口贴合过的工程，升级后也不会自动修复。

## 修复

### 1. 测量真实绘制内容

`src/utils/customCode.ts:485` 的 `measureVisibleBounds()` 改为遍历 root 的可见子树：

- 文本叶子、`img/video/canvas/iframe`、有背景/渐变/边框/阴影的元素都算可见内容；
- SVG 用 `getBBox()` + `getScreenCTM()` 计算真实绘制范围（`:507`）；
- 透明布局容器不参与测量，避免外层 `width:100%` 又把选框撑大（`:531`、`:540`）；
- 只统计与视口相交的区域，四周留 2px（`:556`）；
- 没有任何可绘制子节点时，才退回 root（纯 CSS 背景组件）。

### 2. 丢弃无效的初次测量

`src/components/CanvasViewport.tsx:2323` 的 `handleCustomCodeBounds()` 增加保护：

```ts
bounds.viewportWidth < 24 || bounds.viewportHeight < 24
|| bounds.width < 4 || bounds.height < 4
```

iframe 还没布局时的 `1×1` 不会再被当成最终尺寸。

### 3. 老工程一次性重算

新增 `customCodeFitVersion`（`src/types/index.ts:434`）：

- 当前算法版本为 `2`；
- 老工程没有这个字段，即使 `customCodeAutoFitted=true` 也允许重算一次；
- 重算后写入 `customCodeFitVersion: 2`，之后用户手动缩放不会再被覆盖；
- 手动缩放路径本身已经设置 `customCodeAutoFitted=true`，保持原有行为。

## 验证

用一个“外层透明容器 + 内部固定 360×222 卡片 + 宽 614×346 的 iframe”复现（和截图里的图表结构一致）：

| 阶段 | iframe 视口 | 选框尺寸 | 内容视觉尺寸 | 右侧溢出 | 底部溢出 |
|---|---|---|---|---|---|
| 修复前 | 614×346 | 321×180 | 约 188×116 | **133px** | **65px** |
| 修复后 | 363×224 | 190×117 | 约 188×116 | **2px** | **1px** |

```json
{
  "w": 18.9,
  "h": 20.7,
  "autoFitted": true,
  "fitVersion": 2,
  "aspect": 1.623
}
```

内容实际比例 `360 / 222 = 1.622`，图层比例 `1.623`，已经贴合。
