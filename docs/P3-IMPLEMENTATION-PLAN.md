# P3 生产运营实施计划

P2 的代码门禁已通过，项目进入 P3 开发阶段。P2 不要求现在联调物理设备；真实设备、身份系统和现场性能验证按 P3 计划推进。

## P3 目标

把 P2 的“只读实时看板”升级为可运营系统：接入真实设备协议，保存历史数据，执行告警规则，支持告警确认、角色权限、审计、监控和容灾。

## 实施顺序

| 阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| P3.0 | 生产身份与租户上下文 | JWT/OIDC 验证、角色和数据源权限二次校验，A 租户无法读取 B 租户 |
| P3.1 | OCPP/MQTT 接入适配层 | 设备事件统一为版本化事件模型，断线、重复、乱序和重放可处理 |
| P3.2 | 当前状态与历史存储 | 明确时序库、保留周期、冷热数据策略，查询有租户和时间范围限制 |
| P3.3 | 规则引擎与告警闭环 | 规则版本化，告警去重、升级、确认、关闭均有状态和操作者 |
| P3.4 | 角色权限与审计 | 管理员、运营人员、只读用户权限清晰；配置、确认和发布都有审计记录 |
| P3.5 | 监控、压测与容灾 | 指标、日志、追踪、告警、备份恢复和容量基线完成 |

## P3 开始前必须确认

- 首批协议：OCPP、MQTT 或其他协议，以及版本。
- 设备规模：设备数、每秒消息数、峰值倍率和在线状态定义。
- 存储选型：TimescaleDB、InfluxDB、ClickHouse 或现有平台，以及保留周期。
- 身份选型：OIDC/JWT issuer、audience、角色字段和租户字段。
- 部署边界：网关、BFF、时序库、消息队列之间的网络访问规则。
- 告警口径：阈值、持续时间、去重、升级、确认和关闭规则。

## P3 验收门槛

1. 真实设备持续上报，状态和历史查询一致。
2. 断网恢复后无重复污染，乱序数据不会覆盖新状态。
3. 租户、角色、数据源和地域权限均通过真实身份测试。
4. 告警从产生到确认、关闭可完整追溯。
5. 经过目标峰值压测，延迟、错误率、内存和恢复时间达到业务指标。
6. 备份恢复、数据保留、敏感信息脱敏和发布审批均有记录。

## 当前实际状态

- P3 已正式进入开发阶段。
- P3 首个基础交付为设备适配器注册表，后续协议适配器统一注册到该边界。
- P3.0 的实时 JWT 租户绑定代码已具备，等待接入真实身份系统。
- P2 现场联调不是 P3 开工前置条件，按后续设备接入计划执行。
- 未确认协议、存储和告警口径前，不实现具体网关或规则引擎，避免产生不可用的假集成。
