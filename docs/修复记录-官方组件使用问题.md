> 排查对象：官方组件面板（MODAO Library，`OfficialComponentsModal`）及其插入画布后的渲染链路。

## 排查方法

1. 新增离线扫描页 `promo/official-sweep.html`：把目录内全部官方组件各自渲染在固定舞台里，检查空白、无文字、控制台报错。

## 第二轮：选框贴合与缩放跳变

### 问题

1. 蓝色选框明显大于组件本身（打点批注 175×113 的框里只有约 94×54 的卡片）。
2. 拖动缩放手柄时，组件会先不动、随后突然变大/变小。

### 根因

- `ScaledUIComponent` 对官方组件用 `Math.max(..., 420, 240)` 作为内容尺寸，把 fit-content 的组件（批注、文档、动态组件等）错误地当成 420×240，导致外框永远比组件大。
- 内容型控件采用等比缩放（`min(sx, sy)`），但单边手柄只改一个方向：外框在变、组件不变，越过临界点后才突然跟随 → 表现为“先不动、再跳一下”。

### 修复

- 官方组件的内容尺寸改为实测「实际绘制的根节点」尺寸，不再用设计槽兜底。
- 插入后首次测量时自动把图层外框贴合组件真实尺寸（`__autoFit`，一次生效，写入 `officialAspect`）。
- 官方组件的所有缩放手柄统一为等比缩放（不再出现单轴死区/跳变）；旧工程元素优先使用记录的真实比例。

### 验证

- 打点批注：外框 94×54 = 组件 94×54，完全贴合（`promo/out/galaxy/selection-hug.png`）。
- 拖动右/下/角手柄：外框与组件逐帧同步（94→103→111→…→164），无跳变。
- 基础卡片、基础按钮同样逐帧同步。
- 243 个官方组件：非等比拉伸 0、溢出 0、空白 0。
- `tsc` 0 error；79 文件 / 416 用例通过；`npm run build` 成功。

## 第三轮：缩放时的“卡顿感”与精准度

### 现象

拖动缩放手柄时，蓝色选框在走，组件内容却慢半拍，看起来一卡一卡，松手前很难判断最终大小。

### 根因

- 外框走的是手势预览：`renderGesturePreview` 直接改宿主 CSS 变量，当帧生效。
- UI 组件内部的 `ScaledUIComponent` 依赖 `ResizeObserver` 重新计算缩放，要等下一次布局/下一帧才更新。
- 实测：外框变化的 50 帧里有 24 帧组件内容没有同步变化（约一半时间慢一帧），外框与内容宽度最多差 4px。

### 修复

- `renderGesturePreview` 在写入外框尺寸的同一帧，直接按最新外框计算并写入内部 `transform`，组件与选框严格同帧。
- `ScaledUIComponent` 在渲染层标记缩放模式（`uniform` / `stretch`），手势预览按同样规则计算，避免松手时回弹。
- 自定义代码（iframe）在缩放手势期间保持起始尺寸、用 `transform` 跟随外框，松手后再真正 reflow 一次，避免逐帧重排 iframe 导致长帧。

### 验证

- 外框变化时组件内容同步率：**50/50 帧**（修复前 26/50）。
- 外框与内容宽度逐帧一致（误差 ≤0.5px）。
- 生产构建下拖动缩放：p50 20ms / p90 34ms / 最大 51ms，无长帧冻结。
- 松手后尺寸与最后指针位置一致（`flushTransformUpdate` 提交最后一次 patch）。
- `tsc` 0 error；79 文件 / 416 用例通过；`npm run build` 成功。

> 说明：开发模式（Vite dev + React 开发构建）在大场景下本身会更慢；判断最终手感请用 `npm run build` 后的预览或安装包。

## 第四轮：高精度与高性能收尾

### 发现的精度问题

- 选框旁的尺寸徽标使用**屏幕像素**（受画布缩放影响），并且手势期间不会刷新——拖动时它一直停在开始前的数值。
- 尺寸/位置在提交时统一四舍五入到 `0.1%`（1080p 下约 1.9px），低缩放下看起来像一格一格跳。
- 手势期间 `ScaledUIComponent` 仍会因 `ResizeObserver` 逐帧 `setState`，与直接写 transform 重复做功。

### 改动

- 尺寸徽标改为**画布像素**并显示 1 位小数；手势快速路径每帧同步更新徽标和位置，不再停留在拖动前的数值。
- 位置/尺寸精度从 `0.1%` 提升到 `0.01%`；底部 HUD 显示 2 位小数（例如 `W 21.88%`）。
- 手势期间跳过 `ScaledUIComponent` 的逐帧状态更新，完全由手势预览直接写 transform；手势结束用 `MutationObserver` 补一次最终测量，React 状态与视觉一致。
- 新增 **Alt + 方向键** 精确改尺寸（默认 0.1%/次，Shift 1%/次），不受画布缩放影响；方向键位置微调也提升到 0.01% 精度。

### 验证

- 徽标拖动实时更新：`420.1 → 426.2 → 428.2 → … → 440.3 px`，与 `W 22.93%` 一致。
- Alt+→ ×3：`420.1 → 425.9 px`（+0.3% = 5.76px），精确到 0.1px。
- 外框与组件内容逐帧同步（0 帧滞后）。
- `tsc` 0 error；79 文件 / 416 用例通过；`npm run build` 成功。

> 重场景（例如带 WebGL/canvas 动画的自定义代码图层）的帧率最终仍取决于该图层自身的动画开销；已做到缩放本身不再触发 iframe 逐帧重排。需要更极致的流畅度时，可以在手势期间暂停非选中图层的动画，这属于下一阶段的优化。

## 第五轮：自定义代码组件的白底、遮挡与裁切

### 问题

自定义代码组件在预览/画布里出现不透明白底，固定尺寸内容被 iframe 裁切。

### 根因

- 应用根节点是 `color-scheme: dark`，沙箱 iframe **继承了该值**。Chromium 在 dark color-scheme 下会把透明文档的 iframe 画布合成成不透明白底，`background: transparent` 无效。
- 预览卡片是固定宽高比 + `overflow: hidden`；固定尺寸组件（例如 800×600 的 SVG）比 iframe 大时会被直接裁掉。
- 画布的手势预览会给 iframe 设 `color-scheme`（继承自应用），同样出现白底。

### 修复

- 所有自定义代码 iframe（画布、预览、历史组件）显式设置 `color-scheme: normal`；srcdoc 的 `html` 也写入 `color-scheme: normal`。
- 预览/历史卡片开启 `fitContent`：内容超出 iframe 时等比缩小到完整可见，不再裁切。
- 画布自定义代码同样开启内容适配：超出图层的内容按比例缩放到图层内，松手/缩放时同步。
- 顺手修复：尺寸徽标改为画布像素、手势中实时刷新（第四轮）。

### 验证

- 工作区预览：纯透明组件不再出现白底，深色背景直接透出（`promo/out/galaxy/customcode-transparent-fixed.png`）。
- 固定 800×600 组件在 421×236 预览卡片中完整显示，左上/右下角均在（`promo/out/galaxy/customcode-fit-1.png`）。
- 画布 iframe：`color-scheme: normal`、`background: rgba(0,0,0,0)`。
- 新增回归用例：srcdoc 含 `color-scheme:normal`；`fitContent` 分支生效；iframe 样式带 `color-scheme:normal`。
- `tsc` 0 error；79 文件 / **417 用例**通过；`npm run build` 成功。
