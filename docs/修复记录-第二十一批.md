# 修复记录 · 第二十一批（组合文本翻译）

## 1. 问题

英文模式下仍能看到 `🎬 画布场景`、`淡入 (0.8s)` 这类残留：DOM 翻译器只做「整段精确匹配」，`emoji + 文字` 或「文字 + 单位」就不会命中词表。

## 2. 方案：受限的词组替换

`translateInterfaceText` 在精确匹配与正则规则之后，新增 `translateBySegments()`：

- 只处理 **≤ 30 字符**且包含中文的短文本
- 按词表 key 长度倒序替换（「画布全屏场景」优先于「画布场景」）
- **替换后若仍残留任何中文，则整段放弃翻译**，保证不会出现半中半英
- 结果做缓存（`segmentCache`），避免 MutationObserver 反复扫描造成卡顿

DOM 观察器里的 `translate()` 同步接入该逻辑，并保留原有前后空白。

## 3. 效果

| 文本 | 结果 |
|---|---|
| `🎬 画布场景` | `🎬 Canvas Scene` |
| `淡入 (0.8s)` | `Fade In (0.8s)` |
| `画布场景与未知分组` | 保持原文（剩余中文，放弃） |
| `赛博发光圆环图` | 保持原文（词表未覆盖） |

实测英文界面里，场景卡片已从 `🎬 画布场景` 变为 `🎬 Canvas Scene`，剩余中文只剩工程内容（场景名、项目标题）。

顺带把 `淡入` 的英文从 `Fade` 修正为 `Fade In`。

## 5. 已知边界

- 组合替换不会翻译「用户工程内容」以外的长句；如果一句里既有已知词组又有未知中文，会整体保持原文（宁可中文也不半中半英）
- 词表仍是「中文原文 → 英文」，后续改语义 key 时需要同步调整
