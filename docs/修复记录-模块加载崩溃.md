# 动态模块加载失败 / 错误页修复记录

## 现象

开发服重启后，已经打开的编辑器页面显示：

```text
鲸动交互平台 — 渲染崩溃

Failed to fetch dynamically imported module:
http://127.0.0.1:3000/src/components/VfxMotionCanvas.tsx
```

页面只提供一个「重置工程并重载」按钮，容易让人误以为工程坏了。

## 原因

不是工程数据损坏，也不是 `VfxMotionCanvas.tsx` 本身有编译错误。

开发服务器重启后，旧页面还握着上一次的模块地址和模块图；再次懒加载 `VfxMotionCanvas` 时请求失败，React 错误边界把它当成普通渲染崩溃展示。实测新开页面或刷新后，模块正常返回 `200`，页面不再崩溃。

## 修复

### 1. 区分“模块加载失败”和“真正渲染崩溃”

新增 `src/utils/errorClassification.ts`：

- `isDynamicModuleLoadError()` 识别：
  - Chrome：`Failed to fetch dynamically imported module`
  - Firefox：`error loading dynamically imported module`
  - Safari：`Importing a module script failed`
  - webpack/Vite：`ChunkLoadError` / `Loading chunk`
  - `Unable to preload CSS`

### 2. 错误页不再直接引导重置工程

`src/components/ErrorBoundary.tsx`：

- 模块加载失败时：
  - 标题改为「页面模块需要重新加载」；
  - 说明“开发服可能刚重启，不代表工程损坏”；
  - 主按钮改为「重新加载页面」，只执行 `window.location.reload()`；
  - 不显示「重置工程」按钮。
- 真正渲染崩溃时：
  - 主按钮也是「重新加载页面」（先尝试无损坏恢复）；
  - 「仍无法打开？重置工程」降级为次要按钮，保留清理坏数据的兜底能力。

## 实测

```text
GET /src/components/VfxMotionCanvas.tsx  → 200
新开页面                                  → 未崩溃
刷新页面                                  → 未崩溃
VFX 模块请求                              → 200 / 304
```

复现脚本：`promo/probe-render-crash.mjs`

## 遇到同样画面怎么处理

当前旧页面直接：

- `Ctrl+Shift+R` 硬刷新，或
- 关闭标签页重新打开 `http://127.0.0.1:3000`。

**不要点旧页面的「重置工程并重载」**，那会清空本地工程和素材。
