# 授权与部署变更说明（本次修复）

## 0. 必须立刻做：轮换密钥

`website/server.js` 之前把 **HMAC 签名密钥** 和 **管理员口令的哈希（并可反推明文）** 直接写死在源码里，且该文件在 Git 历史中。请按顺序处理：

1. 生成新的随机密钥（≥ 32 位），例如：`openssl rand -hex 32`
2. 在官网服务器上以环境变量方式启动（**不要**写回源码）：
   ```bash
   LICENSE_SECRET='<新密钥>' ADMIN_PASSWORD='<新管理员口令>' node website/server.js
   ```
3. 登录后台 → 修改管理员密码，确认旧口令失效
4. 删除服务器上的 `data/admin.json`（如果它是用旧默认口令生成的），重启服务后重新设置
5. 把新的 `LICENSE_SECRET` 存进密码管理器；线上已签发的卡密不会失效（HMAC 只用于令牌与设备绑定），但**旧密钥必须视为已泄露**

> 代码已经改为：`LICENSE_SECRET` 缺失或短于 32 位时，所有 `/api/v1/*` 授权接口与后台登录一律返回 503，站点内容照常访问。

## 1. 架构调整：授权只在官网，客户端不再签发

修复前：桌面端启动时用本机 Node 跑 `server/index.js`，同时注册了卡密签发、后台登录、导出授权接口；密钥来自开发默认值，任何用户都能在本机自签卡密。

修复后：

| 组件 | 授权能力 |
|---|---|
| `app_launcher.cs` | 启动本机服务时设置 `AETHER_LICENSE_MODE=disabled`，并优先使用随包分发的 `runtime\node.exe` |
| `server/index.js` | 检测到 disabled 时，`/api/v1/license`、`/api/v1/subscription`、`/api/v1/export`、`/api/v1/checkout`、`/api/admin/*`、`/admin/licenses` 全部 404 |
| 前端 `API_BASE_URL` | 生产构建默认指向 `https://jd-hub.top`（可用 `VITE_API_BASE_URL` 覆盖） |
| `website/server.js` | 唯一签发方；密钥必须来自环境变量 |

另外：

- 管理接口默认只允许 loopback 访问；确需远程管理时显式设置 `AETHER_ALLOW_REMOTE_ADMIN=1`
- 前端授权请求改为 `credentials: omit`（跨域 + `Access-Control-Allow-Origin: *` 下，带 cookie 的请求会被浏览器直接拒绝）；只有显式开启 `VITE_LICENSE_HTTP_ONLY_COOKIE=true` 时才用 cookie

## 2. 工程备份不再需要授权

`ExportModal` 的「工程源数据 (JSON)」现在**不需要授权码、断网可用**，界面上标注「免费 · 离线」。打包交付物（ZIP / 单文件 HTML）仍需服务端短期导出许可。

这解决了"未付费用户导不出自己的数据"和"授权服务不可用则全部导出失败"两个问题。

## 3. 自定义代码改为沙箱运行

`TransparentCustomCodeFrame` 从「同源 Shadow DOM + `new Function`」改为 `sandbox="allow-scripts"` 的 iframe：

- 用户代码运行在 opaque origin，读不到 `localStorage`、Cookie、`aether_auth_token`、BYOK Key
- 只能通过 `postMessage` 与编辑器通信（属性下发、内容回传、运行时诊断）
- 编辑态下 iframe 不拦截指针事件，画布仍可选中/拖动该图层；进入交互预览或双击编辑文字时才接管

已知取舍：

- 组件内的链接/表单不能跳出沙箱（`connect-src 'none'`、`frame-src 'none'`）
- 极少数依赖同源能力的旧自定义组件需要改写

## 4. 构建与打包

```bash
npm run runtime:fetch       # 下载并校验 Node 运行时到 runtime\node.exe
npm run build               # 前端 + 播放器运行时 + 服务端单文件（server/bundle.mjs）
npm run build:exe           # 重新编译启动器（含 runtime 解析与错误提示）
npm run version:check       # 版本号一致性（package.json / installer.iss / 前端兜底）
iscc installer.iss          # 打出安装包（会带上 runtime\node.exe）
```

> 安装包不再携带 `node_modules`：`npm run build` 会用 esbuild 生成 `server/bundle.mjs`，
> 启动器优先运行该单文件。`server/bundle.mjs` 是构建产物，已在 `.gitignore` 中忽略。

`installer.iss` 新增：

- `Source: "runtime\node.exe"` → 安装后用户机器无需再装 Node
- `[UninstallDelete]` 清理 `{app}\data`（授权记录已在服务端，本地不再需要）

- 前端：回退 `dist` 即可
- 授权：把 `AETHER_LICENSE_MODE` 从 `disabled` 改为 `local` 会恢复本机签发能力（**仅限内网演示，切勿随包分发**）
