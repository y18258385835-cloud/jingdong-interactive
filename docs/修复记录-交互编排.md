# 交互编排 2.0 修复记录

> 目标：把「点一下只做一件事」升级成「一次触发按顺序做一套流程」，支持条件、延迟、改变量和切换组件状态。

## 原来的问题

1. 一个图层/热点只能配置一个动作：跳转、弹窗、URL、媒体或改变量。
2. 不能先改数据再跳转，也不能“满足条件才执行”。
3. 不能延迟执行，不能在一个动作里切换组件状态。
4. 想做一套完整原型流程，只能拆成多个图层互相接力。

## 现在的交互模型

在每个交互配置里新增可选的动作序列 `steps`，原来的单动作字段继续兼容：

```ts
interaction: {
  trigger: 'click',
  action: 'none',       // 旧字段，保留兼容
  steps: [
    { type: 'set-variable', variableName: '用户类型', variableValue: 'VIP' },
    { type: 'switch-variant', componentId: 'grp_card', variantId: 'hover' },
    { type: 'wait', delay: 0.5 },
    { type: 'jump', target: 'detail_scene' }
  ]
}
```

每个步骤支持：

- `delay`：执行前等待秒数；
- `condition`：仅当变量满足条件时执行；
- 动作：
  - 修改全局变量；
  - 切换组件副本状态（默认/悬停等）；
  - 跳转场景（执行后结束后续步骤）；
  - 打开网页；
  - 等待。

条件支持：等于、不等于、大于、小于、有值/为真、无值/为假。

## 使用方式

1. 选中一个图层或热点；
2. 右侧检查器切到「交互」；
3. 点「打开动作编排」；
4. 添加步骤，设置动作、延迟、条件和目标；
5. 保存后，右侧会显示「N 步」；
6. 切到演示模式，点击该图层即可执行整套流程。

图层和普通热点都支持。

## 运行时

- `src/utils/interactionRuntime.ts`：统一顺序执行器。
- 编辑器预览：`CanvasViewport` 与 `App` 分别处理元素和热点。
- 导出播放器：`src/utils/export.ts` 的播放器运行时代码同步支持 `steps`。
- 条件中的变量在序列内实时更新：前一步改变量，后一步条件能立即看到新值。
- 跳转场景后结束当前序列，避免在新场景继续执行旧动作。

## 实测

在首页 CTA 文字上配置 3 步：

```text
1. 设置变量 测试变量 = 已触发
2. 等待 0.2 秒
3. 跳转场景 02 · 灵动掌控 · 电影级光影与微控
```

切到演示模式点击该文字后：

- 工程变量出现 `测试变量 = 已触发`；
- 0.2 秒后切换到目标场景；
- 目标场景标题可见。

单测覆盖：

- 条件判断：等于/不等于/大于/小于/真/假；
- 顺序执行；
- 跳转后停止后续步骤；
- 条件不满足时跳过；
- 延迟时间传给运行时。

## 当前 v1 限制

- 编排器目前提供：改变量、切组件状态、跳转场景、打开网页、等待；
- 弹窗场景和媒体弹窗继续走原来的单动作设置；
- 切换组件状态在编辑器预览中会写回当前副本（导出播放器只在本次播放内生效）；
- 暂不支持“否则执行另一套步骤”的分支树，后续可加 if/else。
