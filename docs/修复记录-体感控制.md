# 修复记录 · 体感控制可用性（P1）

## 问题现象

- 体感控制“有时候不能弹出”：点击启动后常直接变成“加载异常”，摄像头画面不出现。
- 摄像头画中画收起后，手势好像失效。
- 每次关闭再开启体感，都要重新加载引擎，慢且容易失败。
- 出错时只显示“加载异常”，分不清是引擎、摄像头权限还是视频节点问题。

## 根因

1. **视频节点只在画中画展开时挂载**
   `<video>` 位于 `isCameraExpanded && (isReady || isLoading)` 的容器里，而画中画默认收起。
   `start()` 在 `getUserMedia()` 返回后找不到 `videoRef.current`，直接抛 `no-video`，状态变成 error。
   只有在权限弹窗期间刚好点开画中画，才会“有时候能用”。

2. **收起画中画会卸载 video**
   即使启动成功，收起后视频节点被移除，识别循环拿不到帧源，只剩空转的 RAF —— 手势自然不触发。

3. **每次开关都销毁模型**
   `enabled` 变化的 cleanup 调用 `stopInternal(true)`，关闭时释放 MediaPipe 模型；再次开启要重新下载 CDN + 模型，慢且易受网络影响。

4. **错误恢复路径不对**
   `retry()` 只重载引擎；摄像头失败时点“重试”仍然重载引擎，问题不会恢复。

## 修复

- **摄像头节点常驻**：画中画收起时把 video/canvas 放到屏幕外保持 2×2 渲染，展开时回到胶囊上方；识别循环始终有帧源。
- **启动前等待 video 挂载**：`start()` 最多等 20 帧，避免 `getUserMedia` 比 React 挂载更快导致误报 `no-video`。
- **开启即启动**：用户在水合完成后点“开启体感”会自动展开画中画并请求摄像头；打开一个已开启体感的工程不会自动调用摄像头（避免加载即开摄像头）。
- **模型缓存**：关闭体感只停摄像头/识别循环，保留 MediaPipe 模型；再次开启秒开。仅组件卸载时释放模型。
- **区分错误类型**：引擎未就绪显示“引擎加载异常”，引擎就绪但摄像头失败显示“摄像头异常”；重试分别走引擎重载或摄像头重启；错误详情以卡片展示。
- 收起画中画不再影响手势识别。

## 第二轮：P1 打磨

### 灵敏度

- 修正方向：数值越大越灵敏，`1.0×` 保持原有默认行为。
- 每条手势绑定的“灵敏度”现在真正参与判定：作为全局灵敏度的倍率，只影响对应手势（左右滑、挥手各自计算）。

### 呼出菜单

- `show_menu` 不再是空动作：手势触发后切换底部播放控制栏的显示/隐藏。
- 文案改为「呼出/收起控制栏」，Toast 同步。

### 离线引擎（重点）

体感引擎原先完全依赖 MediaPipe CDN，国内网络/断网时会一直加载失败。现在：

- 将 `vision_bundle.js`、SIMD/非 SIMD 两套 wasm、`hand_landmarker.task` 放入 `public/mediapipe/`，随应用分发。
- 加载顺序改为：**本地优先 → jsdelivr → unpkg → npmmirror → Google Storage**。
- 本地文件缺失/损坏时自动降级 CDN，不会卡死。
- Vite 监听排除 `public/mediapipe`（Windows 下大文件会触发 EBUSY）。
- 安装包只保留 `dist\mediapipe` 一份，`public` 副本排除，避免双倍体积。
