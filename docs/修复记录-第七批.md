# 修复记录 · 第七批（MCP 实操验收 + 两个真实 Bug）

本轮用 MCP 真正驱动了一次「导出 → 修改 → 导入」闭环，发现并修复了两个用户可感知的问题。

## 1. MCP 实操发现的问题

### A. `layer_set_text` 写错字段（静默无效）

文本图层在数据里用的是 **`content`**，而 CLI/MCP 写的是 `text`：

- `layer_list` 读不到文本（返回 `undefined`）
- `layer_set_text` 报告成功，但编辑器完全不显示新文案

修复：

- `tools/aether-cli/core.mjs`：读优先 `content`、兼容旧 `text`；写时按图层实际字段落笔
- `validate` 新增提示：文本图层缺少 `content/text`
- 单测 fixture 改为真实字段，并验证写回结果

### B. 自己导出的 JSON 无法重新导入（P1）

导出面板写着「可随时在其他鲸动交互平台中重新导入」，实测直接报 **工程数据校验失败**。原因有两个：

1. `src/core/schema/validate.ts` 的 `IN_ANIMS` 枚举比 `InAnimType` 少 6 个值，官方模板使用的 `perspective-in` 不在白名单里
2. 导出的 JSON 没有 `schemaVersion`（原始数据校验直接失败，只能靠 normalize 的迁移兜底）

修复：

- 补齐 `IN_ANIMS` / `OUT_ANIMS` 与类型定义同步（`neon-glow-in`、`scan-reveal`、`hologram-in`、`stardust-in`、`energy-pop`、`perspective-in` / `neon-out`、`particle-out`、`hologram-out`、`scan-out`）
- JSON 导出统一写入 `schemaVersion`
- 新增回归测试：逐个校验官方模板使用的入场动效

## 2. 继续拆包：看板组件 HTML

`dashboard-embedded-components.html?raw`（256 KB）之前被 App 静态引入。
